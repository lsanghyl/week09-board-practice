# Week 09 - 검색·정렬·페이지네이션 게시판 개선

## 1. 프로젝트 소개

1,000개의 게시글 데이터를 활용하여 검색, 정렬, 페이지네이션 및 비동기 검색 기능을 검증하고 개선하는 실습 프로젝트입니다.

기존 예제 코드를 기반으로 각 기능의 동작을 확인하고, 필요한 부분을 수정하여 게시판의 안정성과 사용성을 개선하였습니다.

## 2. 실행 방법

### 실행 환경
- Node.js
- Express
- 웹 브라우저

### 실행 명령어

```bash
npm install express
node server.js
```

실행 후 브라우저에서 다음 주소로 접속합니다.

http://localhost:3000

## 3. 주요 기능

### 검색 및 정렬
- 게시글 제목 및 본문 검색
- 검색 결과가 없는 경우 처리
- 최신순, 오래된순, 조회순 정렬
- 조회수 동점 시 ID 내림차순 정렬
- 정렬 키 화이트리스트를 통한 잘못된 입력 처리

### 페이지네이션
- 오프셋 기반 페이지 이동
- 페이지 정보(meta) 반환
- 검색어 및 정렬 변경 시 첫 페이지 초기화
- 커서 기반 게시글 추가 조회
- 커서 모드에서 제목 및 본문 검색
- 마지막 페이지 도달 시 더 보기 종료

### 비동기 검색
- 300ms 디바운스를 이용한 검색 요청 제어
- AbortController를 이용한 이전 요청 취소
- AbortError 예외 처리

### URL 상태 복원
- URLSearchParams를 이용한 검색 조건 동기화
- 새로고침 이후 검색 및 페이지 상태 복원
- 뒤로 가기를 통한 이전 상태 복원

## 4. 핵심 개념

### 4.1. 오프셋과 커서 페이지네이션

오프셋 페이지네이션은 페이지 번호로 이동하는 일반 게시판에 적합합니다. 전체 페이지 수를 표시하고 원하는 페이지로 직접 이동할 수 있습니다.

커서 페이지네이션은 무한 스크롤이나 더 보기 방식에 적합합니다. 마지막으로 조회한 게시글의 ID를 기준으로 다음 데이터를 조회합니다.

### 4.2. 디바운스와 요청 취소

디바운스는 사용자의 연속 입력이 끝난 후 일정 시간이 지나면 요청을 실행하는 방식으로, 불필요한 HTTP 요청을 줄입니다.

AbortController는 새로운 검색 요청이 발생할 때 이전 요청을 취소하여 불필요한 처리를 줄이고 오래된 응답이 최신 검색 결과에 영향을 주는 문제를 방지하는 데 사용됩니다.

### 4.3. limit + 1 조회

커서 페이지네이션에서 요청한 개수보다 한 개 더 조회하여 다음 데이터의 존재 여부를 판단합니다.

예를 들어 limit이 10이면 최대 11개를 조회합니다. 11개가 조회되면 다음 데이터가 존재하므로 hasNext를 true로 설정하고, 사용자에게는 10개만 반환합니다.

### 4.4. offset 및 totalPages 계산

```text
offset = (page - 1) × limit
totalPages = ceil(totalCount / limit)
```

예를 들어 전체 게시글이 83개이고 페이지당 10개를 표시한다면 전체 페이지 수는 9페이지입니다.
